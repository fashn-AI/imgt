Estimated monthly total.
Lower is cheaper.

2.25M fresh images per month. Assumes 10M total image requests, 120 KiB outputs and containers awake all month. Includes the Workers plan, CPU, RAM, disk, Durable Objects, R2 and modeled output transfer. Basic is ¼ CPU / 1 GiB per container, tested locally only.

Both providers use the same modeled image volume. Vercel uses iad1 on-demand rates before credits and delivery charges. imgt assumes shared Cloudflare allowances are available. These are estimates, not invoices.

Test method, reliability and pricing assumptions

The traffic target comes from FASHN's projects together: about 2.25M monthly transformations and a busiest observed 15-minute interval of roughly 2.9 transformations/second. Tests at 10 and 20/second add headroom; the dashboard does not reveal second-by-second peaks.

All configurations retain source validation, eight active jobs per shard, bounded waiting, deduplication and a 60-second transform deadline. Small containers use one native encoder; 2-CPU containers use two. Cache hits avoid compute.

Local Docker enforces CPU and RAM limits without swap. Origins are replayed in memory and R2 writes are delayed 300 ms. These timings do not include Cloudflare provisioning or real network latency. The basic tier cannot run through the current native container scheduling API.

Live tests use real FASHN PNG sources from one client in Brazil. Each profile runs separately. Latency charts show successful-response p95 alongside errors; errors cannot be treated as fast responses. Cold starts and maximum latencies are included in the linked report.

Cost estimates use 0.14 consumed CPU seconds per transform, a 30-day month, North American container output transfer and 30 days of retained derivatives. A 30-day R2 lifecycle rule is required for this storage estimate. Total requests and average output size are assumptions, not values inferred from Vercel cache units. Source transfer, excess logs, storage for Durable Objects, taxes and support time are excluded.
